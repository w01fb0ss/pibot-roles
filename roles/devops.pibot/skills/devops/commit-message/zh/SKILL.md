# 提交说明

改动：{改动概要}

## 步骤
1. 先看项目最近的提交记录（git log --oneline -n 20），沿用它的语言、前缀和格式（比如 `feat:`、`fix(scope):` 或中文前缀）。
2. 看 `git diff --staged`（没有暂存时看 `git diff`），确认这次改动只做一件事；混了几件事就建议拆成几个提交。
3. 写标题：一行，不超过约 50 个字符（中文约 30 字），用祈使语气说明「做了什么」，结尾不加句号。
4. 写正文（改动不是一眼能看懂时）：空一行后写「为什么改」和「有什么影响」，每行不超过约 72 个字符。
5. 修 bug 时写上复现方式和原因；有关联的问题编号就附上。
6. 不写进提交说明：密钥、内部网址、个人信息、本机路径。

## 模板

```
<前缀>: <做了什么>

<为什么要改：原来的问题或需求>
<怎么改的：关键思路，不逐行复述代码>
<影响：兼容性、迁移、需要注意的地方>
```

## 注意
- Git 操作遵守本次实际权限；生成提交说明不代表已经授权提交、合并或推送。
- 用户没有要求时不要自己提交、推送或改写历史；只给出建议的提交说明。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
