# 部署检查清单

服务：{服务}　环境：{目标环境}

每项写「已确认 / 不适用 / 有问题」。命令服从当前权限与目标环境的真实授权，环境未指定时不能默认生产。

## 发布前
- [ ] 这次发布包含哪些改动（提交列表或变更说明），有没有数据库迁移、配置变更
- [ ] 构建和测试在 CI 或本地已通过（贴结果）
- [ ] 新的配置项、环境变量已在目标环境准备好（只核对名字，不打印值）
- [ ] 数据库或关键数据已备份，并确认备份能恢复
- [ ] 回滚办法写好了：回到哪个版本、怎么做、迁移能不能撤回
- [ ] 选好发布时间，避开高峰；相关的人知道
- [ ] 能先在预发或用 --dry-run 演练的已演练

## 发布中
- [ ] 按步骤执行，每步记录时间和结果
- [ ] 分批或灰度发布时，先小范围观察再扩大
- [ ] 出现异常立刻停下，按回滚办法处理，不在现场临时改代码

## 发布后
- [ ] 健康检查、关键接口、关键页面正常
- [ ] 错误率、延迟、资源使用和发布前对比没有明显变化
- [ ] 日志里没有新的报错
- [ ] 更新变更记录，通知相关的人

## 输出
```
**发布内容**：…
**检查结果**：有问题的项及处理
**执行记录**：时间 —— 操作 —— 结果
**验证结果**：…
**回滚办法**：…
```

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
