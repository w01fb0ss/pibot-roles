# 术语表

原文：{原文}　方向：{语言方向}

## 步骤
1. 先问用户有没有现成的术语表或风格指南；有就以它为准，只补充缺的。
2. 通读原文，找出：
   - 专业术语、反复出现的概念
   - 产品名、功能名、界面上的按钮和菜单名
   - 人名、机构名、地名
   - 不翻译的内容（代码、变量、占位符（如 %s、%1$d）、命令、文件名）
3. 每个词条定一种译法：优先行业通行译法和官方译法；查到多个译法时列出来并说明选择理由。
4. 拿不准的词条标「待确认」，翻译时先用暂定译法，并在译注里列出。
5. 翻译过程中遇到新术语，随时补进表里；交付时附上最终版术语表。

## 模板
```
| 原文 | 译文 | 词性 / 类别 | 说明（出处、上下文、不要用的译法） | 状态 |
|---|---|---|---|---|
| 工作区 | workspace | 名词 / 界面 | 不用 workplace | 已确认 |
| %s | %s | 占位符 | 原样保留 | — |
```

术语表可以存为工作文件夹里的 glossary 文件，方便以后复用（写入遵守本次实际权限和审批结果）。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
