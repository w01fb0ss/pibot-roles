# 设计评审清单

设计稿：{设计稿}
用户任务：{用户任务}

## 检查项
1. **任务**：用户能否一眼看出这里能做什么、主要按钮是哪个？完成任务要几步，能不能更少？
2. **层级**：最重要的信息最显眼吗？字号、粗细、颜色、留白有没有拉开层次？
3. **一致性**：组件、图标、文案语气、间距和项目已有界面一致吗？
4. **状态**：空状态、加载、出错、内容过长、没有权限、离线都设计了吗？
5. **反馈**：点击、提交、保存后用户能知道结果吗？危险操作有确认和撤销吗？
6. **文案**：按钮写动作（「保存」而不是「确定」），提示说清问题和下一步，中英文长度都放得下。
7. **可访问性**：对比度、焦点、键盘、点击区域大小；信息不只靠颜色区分。
8. **主题与适配**：深浅色都清楚；窄屏怎么排。

## 输出
```
**总体印象**：一两句
**必须改**
1. 位置（区域 / 元素）—— 问题 —— 为什么 —— 建议
**建议改**
1. …
**做得好的地方**
**需要设计补的状态**
```
意见指到具体元素，说明原因；不说笼统的「不好看」。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
