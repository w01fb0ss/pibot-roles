# 项目计划

项目：{项目}　截止：{截止时间}　成员：{成员}

## 步骤
1. 写清目标和成功标准，以及不在范围内的事。
2. 从交付日倒推 3–6 个里程碑，每个里程碑有可检查的产出。
3. 把每个里程碑拆成任务：一个任务 0.5–3 天、一个负责人、一个交付物、一个完成标准。工作量请负责人估。
4. 标出依赖和关键路径（哪条链上的任务延期会推迟整体）。
5. 列风险：可能性、影响、应对办法、谁跟进；至少想到人手、技术、外部依赖、需求变化四类。
6. 约定节奏：多久同步一次、用什么格式汇报（可用「周报」技能）。
7. 在群里统筹时：同一个文件夹同一时间只安排一个成员写（写锁），其他成员先读、先出方案。
8. 日期写具体日期，不写「下周」。

## 使用边界

优先使用已有信息；用户的数量、格式和任务范围优先于本文默认模板。工具权限、主目录/附加只读、Plan 模式与预算以当次实际能力为准；不换工具规避拒绝。这里只给工作方法，不授权写入、命令、付费、发送、提交或发布；未执行/验证的步骤如实标明。
