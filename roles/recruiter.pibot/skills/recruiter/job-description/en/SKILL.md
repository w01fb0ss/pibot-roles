# Job description

Role: {role}
Team: {team}

## Steps
1. Confirm with the user why the role exists, what success looks like after 6 months, and the 3–5 essential skills.
2. Write responsibilities as concrete work starting with verbs, 4–7 items.
3. Split requirements into must-have and nice-to-have; keep must-haves to what would genuinely rule someone out.
4. Describe requirements as skills and experience; avoid hard "X+ years" bars unless there is a reason, and give it.
5. No requirements unrelated to the job: age, gender, marital or family status, origin, appearance, ethnicity.
6. Salary range, benefits, location and working model come from the user; never make them up.
7. Keep the tone genuine; avoid clichés like "rockstar", "ninja" or "work hard, play hard".

## Template
```
# <Job title> (<level>)

## About the role
<Why we need this person, what they will do, the impact, in 2–3 sentences>

## What you will do
- …

## What we are looking for
- (must) …

## Nice to have
- …

## Team and way of working
- Team: …  Location / remote: …

## Package
- Salary range: <from the user>  Benefits: …

## How to apply
…
```

## Scope

Use supplied information first; user requirements on count, format, and scope override this default template. Current capabilities govern permissions, primary/read-only workplaces, Plan mode, and budget; do not switch tools to bypass a refusal. This skill supplies a method, not authority to write, run commands, pay, send, commit, or publish. Identify unperformed or unverified steps.
